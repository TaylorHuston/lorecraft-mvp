   - Evidence: app `AGENTS.md` still describes a one editable/resettable playtest world and says to avoid slash commands, while the app now has World/Adventure, multiple seeded Worlds, slash utilities, Story, and Guide.

4. `lifecycle-drift` - manual verification gaps are inconsistent with closed change records.
   - Evidence: several LC-001 `Verification Gaps` still say manual browser confirmation is pending even where closed tasks accepted the gap or captured successful manual use.
   - Impact: acceptance state is ambiguous.
   - Recommended workflow: artifact-only reconciliation; mark accepted gaps explicitly where no further manual testing is required.

5. `ownership-drift` - S7 and movement/state ownership are too broad.
   - Evidence: S7 owns prompt assembly, debug logging, raw request storage, generation settings, and some trigger behavior. S1/S6/S10/S12/S14 all touch movement or mutation boundaries.
   - Impact: future changes can update the wrong Story and create duplicate requirements.
   - Recommended workflow: artifact-only Story notes now; split only when new implementation work needs it.

### SUGGESTION

1. `verification-drift` - Add explicit `/look` privacy and visibility scenarios.
   - Current code appears to omit hidden facts and reject targets outside visible scope, but the Epic should own that behavior directly.

2. `prototype-boundary` - State that Story inserts are currently direct client-callable Convex mutations.
   - That is acceptable for the local prototype, but should be visible as a future auth/permission hardening point.

3. `future-split-trigger` - Keep S11 as supporting verification for now.
   - If E2E/CI becomes app-wide infrastructure, move its durable truth into `docs/testing.md` and a separate verification Epic.
